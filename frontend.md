# Iverto AI — Frontend Specification Document

## 1. Overview
This document outlines the frontend architecture, design system, and page structures for the **Iverto AI Web Dashboard** (`/Software-main/frontend`). The frontend is built using **React**, **Vite**, **TypeScript**, and **Tailwind CSS**. It serves as a comprehensive web interface with role-based access for Super Admins, Admins, and Security personnel to monitor camera streams, manage alerts, and handle device configurations.

## 2. Architecture & Tech Stack
*   **Core Framework:** React 18+ with Vite for fast HMR and optimized builds.
*   **Language:** TypeScript for type safety and better developer experience.
*   **Styling:** Tailwind CSS integrated with custom CSS variables (`index.css`) for a highly customized theme.
*   **State Management:** Redux Toolkit (`store/`) for global state (auth, ui) alongside React Context (`contexts/`) for specific domains (WebSocket, Local IP, Language).
*   **Routing:** React Router v6 (`react-router-dom`) with protected routes (`AuthGuard`) and role-based redirection.
*   **Real-time Communication:** WebSockets via a custom `WebSocketProvider` for live camera feeds and real-time alerts/anomalies.

## 3. Design System & Aesthetics
The application utilizes a **modern light theme** featuring sleek curves, glassmorphism, and a vibrant primary accent color, moving away from generic corporate designs to a premium security feel.

### 3.1. Color Palette
*   **Background (Primary):** White to Light Gray gradient (`#fafafa` to `#f5f5f5`).
*   **Primary Accent:** Vibrant Pink/Red (`#cd0447` to `#e91e63`). Used for active states, primary buttons, and critical highlights.
*   **Success:** Emerald Green (`#10b981`). Used for online camera status and successful actions.
*   **Warning:** Amber/Orange.
*   **Danger/Offline:** Crimson Red (`#ef4444`).
*   **Cards/Surfaces:** Semi-transparent white (`rgba(255, 255, 255, 0.8)` to `0.9`) to support glassmorphism.

### 3.2. Typography
*   **Font Family:** **Poppins** (`@fontsource/poppins`). A geometric sans-serif font providing a clean, modern, and readable interface.

### 3.3. Visual Effects & UI Paradigms
*   **Glassmorphism:** Extensive use of background blur (`backdrop-filter: blur(20px)`) and semi-transparent backgrounds on cards, sidebars, and badges.
*   **Curved Design:** Soft, rounded corners on components. Cards use up to `20px` to `24px` border-radius.
*   **Micro-Animations & Hover States:**
    *   Cards lift up (`translateY(-4px)`) and increase shadow on hover.
    *   Smooth pulsing animations for online/offline status dots (`pulse-green`, `alert-pulse`).
    *   Gradient text and icon backgrounds.
*   **Responsive:** Mobile-first approach with custom media queries optimizing typography, padding, and grid layouts for mobile, tablet, and desktop (`.mobile-card`, `.tablet-card`, `.desktop-card`).

## 4. Application Routes & Pages

The application employs a `RoleBasedRedirect` system directing users to specific dashboards based on their role (`superadmin`, `admin`, `security`, or default user).

### 4.1. Authentication Flow
*   **`/login`**: The primary login screen.
*   **`/register`**: User registration.
*   **`/pending-registration`**: Status page for users awaiting admin approval.
*   **`/otp-verification`**: Multi-factor authentication step.

### 4.2. Core Dashboards (Role-Based)
*   **`/superadmin` (SuperAdmin Dashboard):** Highest level overview for system administrators.
*   **`/admin-dashboard` (Admin Dashboard):** Management overview for organization admins, including use-case purchases and configuration.
*   **`/dashboard`:** General dashboard for standard authenticated users.
*   **`/security-cameras`:** A specialized, likely sidebar-less, focused view for security personnel dedicated purely to monitoring.

### 4.3. Feature Pages
*   **`/cameras`**: Grid view of all camera streams. Camera cards display online/offline status with color-coded gradients and pulsing indicators.
*   **`/alerts`**: Centralized log and notification center for system events, anomalies, and unauthorized access attempts.
*   **`/ai-report`**: Analytics and reporting interface visualizing data generated by the edge-node AI models (e.g., traffic density, demographic analysis).
*   **`/customers`**: Management interface for client/customer data, accessible by higher-tier roles.
*   **`/profile`**: User account settings and personal preferences.

## 5. Key Components & Features
*   **GlobalAnomalyNotifier:** A global component that listens to the WebSocket connection and pops up alerts/toast notifications when critical security events occur, regardless of the page the user is currently viewing.
*   **Error Boundary:** A robust fallback UI that catches JavaScript errors, specifically ignoring expected network or WebSocket disconnects to prevent unnecessary app crashes.
*   **Custom Toaster:** A unified notification system for success/error messages.
*   **Data Initializer:** A background service (`dataInitializer`) that fetches and caches necessary startup data (like camera lists) without blocking the initial UI render.
